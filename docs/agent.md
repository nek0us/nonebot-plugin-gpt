# 智能体使用说明

## 启用条件

智能体默认关闭，且所有入口只允许 NoneBot 的 `SUPERUSERS` 使用；`gpt_manage_ids` 不会授予智能体权限。

```env
gpt_agent_enabled=true
gpt_agent_confirm_timeout=60
gpt_agent_plan_timeout=300
gpt_agent_session_approval_timeout=1800
```

重启机器人后生效。待确认操作、临时授权、计划编号和审计记录都只保存在内存中，机器人重启后会清空。

## 基本命令

```text
智能体 工具
智能体 状态
智能体 模型
智能体 环境
智能体 审计 20
```

`状态`、`模型` 和 `环境` 是只读工具。环境诊断不运行系统命令，Windows 与 Linux 都会尽力返回系统、CPU、内存和磁盘信息；无法可靠获取的字段会显示为不可用。

## 计划与执行

先生成计划：

```text
智能体 计划 检查当前运行环境
```

模型只会得到插件已注册的工具名称、参数结构和权限类别。它必须返回 JSON 计划；插件会重新校验工具名和参数，拒绝 shell 命令、未注册工具和不合法参数。

计划本身不会执行任何操作。计划通过后会返回编号：

```text
智能体 执行 <计划编号>
```

计划编号默认五分钟有效，仅能由原超级用户在原聊天范围执行一次。需要确认的工具会继续返回确认编号：

```text
智能体 确认 <确认编号>
智能体 取消 <确认编号>
```

## 权限与临时授权

工具权限由插件代码定义，而不是模型决定：

| 类别 | 策略 |
| --- | --- |
| 本机只读 | 可自动允许，或在当前聊天范围申请临时授权 |
| 网络读取 | 逐次确认 |
| 本机写入 | 逐次确认 |
| 进程控制 | 逐次确认 |
| 高风险变更 | 逐次确认，不支持长期授权 |

当前仅允许为“本机只读”申请临时授权：

```text
智能体 授权 本机只读
智能体 确认 <确认编号>
智能体 授权列表
智能体 撤销授权
```

临时授权绑定原超级用户和原聊天范围，到期或重启后自动失效。网络、写入、进程控制和高风险变更不能通过临时授权绕过确认。

## 受管服务

只有管理员在 `gpt_agent_managed_services` 中显式配置的服务才会注册状态和重启工具。模型无法传入任意进程名、PID 文件、主机、端口或命令。

```env
gpt_agent_managed_services='[
  {
    "name": "bot",
    "kind": "pid_file",
    "pid_file": "/run/nonebot.pid",
    "restart_command": ["systemctl", "restart", "nonebot"],
    "restart_check_seconds": 5
  },
  {
    "name": "local-api",
    "kind": "tcp",
    "host": "127.0.0.1",
    "port": 8080
  }
]'
```

- `pid_file`：读取 PID 文件并检查本地进程状态。Windows 使用 `OpenProcess`，Unix 使用 PID 存在性检测。
- `tcp`：仅探测配置的主机和端口连通性，属于网络读取，需要确认。
- `restart_command`：可选参数数组。仅使用配置数组启动子进程，不经过 shell，也不会显示命令输出。
- `restart_check_seconds`：重启命令退出后等待复检的秒数，范围 `0-30`，默认 `3`。

带有 `restart_command` 的服务会出现“重启受管服务”工具。它属于进程控制，必须经过计划、执行编号、确认和审计；重启后仅复检同一服务已配置的 PID 或 TCP 目标。

## 审计与边界

`智能体 审计` 仅显示当前运行中的固定事件，例如计划创建、确认取消、工具调用和服务重启。它不保存任务原文、模型理由、参数值、命令内容、验证码或账户凭据。

智能体不是安全边界。真正的边界始终由工具白名单、参数校验、超级用户限制、确认事务和管理员配置共同构成。
